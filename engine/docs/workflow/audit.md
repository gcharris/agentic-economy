## [critical] A draft can rename itself: `ctx.node_id` is public and Collect trusts it, so a seat writes another node's Oak Table, purse and epistemics with no gate
/Users/gch2021/Dev/Multi-Asset Workflows/engine/src/tick.rs:346 · Law 1 (parallel encapsulation) and Law 2 (Oak Table is local)

claim: The Draft phase is not encapsulated. `DraftContext` (node.rs:360-361, `pub struct DraftContext { pub node_id: NodeId, ...`) exposes its identity as a writable field, and `Engine::collect` re-derives the owner from that field instead of from the job it issued: `let node_id = ctx.node_id;` (tick.rs:346) then `let Some(node) = self.nodes.get_mut(&node_id) else { return };` (tick.rs:352). Everything after that line — `node.purse.burn_to_empty(ctx.burned)` (356), `node.epistemics = ctx.epistemics` (359), `node.oak_table.leave_paper(p)` (370), `node.halt(...)` (379) — lands on whichever node the seat named. A seat on house A that sets `ctx.node_id = B` puts papers on B's table, burns B's compute, overwrites B's Φ and can halt B, and A's own draft is never reconciled. lib.rs:11-14 says a draft 'has *no reference* to ... other nodes' and 'The type system enforces this'; tests/golden_invariant.rs:22 says 'A seat that tries to reach the graph has nothing to reach for'. Both are false: the reference is the u64 the seat is handed (or guesses).

evidence: tick.rs:345-383. The only 'cross-node write' the module doc admits (tick.rs:8-10, 624-626) is the approved Dispatch delivery in commit(); this path writes B's table with `envelopes_minted == 0`, `approved == 0`, and no `Delivered` event. Repro asserts B's oak root changed, a paper titled 'poison' is on B's table, B's compute fell by exactly 123.0, B's Φ is 0.05, and A's table is empty.

repro: cargo test --test audit_isolation forged_node_id_writes_another_houses_oak_table_without_a_gate (lane copy, tests/audit_isolation.rs). street(cfg(101), 2, 600.0, 1); replace_staff(A, [Impersonator{victim: B}]); replace_staff(B, []); tick().

fix: Never read identity back from the draft. Have the executor return `(NodeId, DraftResult)` keyed by the `DraftJob` the engine built (or keep a `Vec<NodeId>` parallel to `jobs` and zip by index, which `DraftExecutor::run` already promises to preserve), and ignore/`debug_assert_eq!` `ctx.node_id`. Make `node_id`, `tick`, `parent`, `stage` read-only (private fields with getters, or a separate `DraftIdentity` the seat cannot mutate). Reconcile epistemics by replaying recorded events (`ctx.handovers: Vec<(ModelTier, f64)>`) rather than copying the whole struct back. Add a law-1 test that a forged `node_id` is dropped.

## [critical] Forged `ctx.node_id` yields envelopes signed with the victim's secret; the Letter Slot approves them and house A transfers house B's liquidity to itself
/Users/gch2021/Dev/Multi-Asset Workflows/engine/src/tick.rs:399 · Law 3 (the Gate) and Law 4 (sovereignty), via the Law 1 hole

claim: Because Collect resolves the node from `ctx.node_id`, it also signs every proposal in that context with that node's secret: `let auth_signature = node.sign(&payload_hash, tick);` (tick.rs:399) where `node` is the victim. `BoundaryView::signature_valid` (boundary.rs:96-101) checks the signature against `node_secrets[env.initiator]`, i.e. the same victim secret, so preflight passes. The 'Auth_Signature' of the design (01_CORE_ARCHITECTURE §2) is therefore forgeable by any seat in any other house at Stage 2 and above; at Stage 1 the same forgery parks an envelope at B's Door where B's human sees 'pay 150.0 tokens: ...' as if B had asked.

evidence: Repro: street scenario at active_scale Street, A staffed with `Thief{victim: B, amount: 150}`, B unstaffed. fix: Same root fix as finding 1 (bind identity to the job, not the context). ## [medium] The `Send + 'static` proof covers `DraftContext`, not the seat: `Agent: Send + Sync` admits any captured `Arc<Mutex<_>>`, so seats on different houses read each other's snapshots inside the Draft phase
/Users/gch2021/Dev/Multi-Asset Workflows/engine/src/node.rs:460 · Law 1 (parallel encapsulation) — the claim at lib.rs:13-14 'The type system enforces this'

claim: `GOLDEN_INVARIANT_LAW_1` (node.rs:392-395) proves only that the *context* holds no borrow. The seat is `pub trait Agent: Send + Sync` (node.rs:460), stored as `Arc<dyn Agent>` and cloned into every job (`Some(s) if !s.is_empty() => s.clone()`, tick.rs:292). `Arc<Mutex<T>>` is `Send + Sync`, so a seat built with a shared mailbox is accepted by the same bound, runs under either executor, and can push its `OakSnapshot`, purse and node name where another house's seat reads them in the same tick — with no gate, no tax and no event. The bound cannot express 'holds no shared state', so the sentence 'the type system enforces this' is not true of the thing that actually runs. A seat cannot reach the live `Engine` (`dyn Agent` is `'static` and `tick` holds `&mut self`), but it can hold a clone of `SovereignGraph` taken at construction, or any host-updated `Arc<RwLock<_>>`.

evidence: Repro: three houses each staffed with `Gossip{mailbox: Arc<Mutex<Vec<(NodeId, String, f64, Hash32)>>>}`; `assert_send_static::<Gossip>()` compiles; after one tick the mailbox holds all three snapshots and at least three 'overheard' papers naming other houses' purses and oak roots are on tables. Under `TokioExecutor` the same seats run concurrently and the mutex still serialises them.

repro: cargo test --test audit_isolation seats_can_share_state_across_houses_through_a_captured_arc_mutex

fix: State the actual trust boundary honestly: seats are trusted code; the type proof only isolates the context. If real isolation is wanted, construct seats per job from a `Fn(NodeId) -> Box<dyn Agent>` factory that is itself checked to be stateless (e.g. require `Agent: Copy` for statistical seats), or run untrusted seats out-of-process/wasm with only the serialized `DraftContext` as input and a serialized `DraftContext` as output (the struct is already `Serialize + Deserialize`, which is the right shape for this). Rewrite the law-1 test so it does not assert the impossible.
